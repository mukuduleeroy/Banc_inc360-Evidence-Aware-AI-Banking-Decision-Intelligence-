# Hackathon demonstration value and technical risk

## Option A — retain the accepted system

Demonstrate original Inactivity Intelligence/observed recency, verified historical three-model comparison, six-gate decisions and manager review; Phase 9 compatible ingestion/rollback; Phase 10B independent illustrative upsell and explicit source-derived high-activity proxy. The existing 647-case source-bound acceptance and recorded browser demonstrations verify these implemented scopes.

Advantages: no new model artifact dependency, no new fitting/inference failure mode, unchanged protected state, accurate existing metrics/limitations and an already reproducible local narrative. Practical historical AI is present; it does not need to be falsely described as operational inference. The churn requirement remains partially addressed through inactivity evidence, not confirmed customer attrition or a live probability.

Risk is mainly presentation honesty: do not call ROC-AUC accuracy, Precision@500 retention success, current sales ABSTAIN model uncertainty, high activity profit, or synthetic upsell an actual BancABC offer. Keep the separate companions distinct from original dashboard dataset switching. No application was launched or reviewed persistently during this audit.

## Option B — possible isolated predictive research companion

If separately authorized and validated, a point-in-time snapshot→frozen preprocessing/model→eligible-customer relative inactivity ranking could demonstrate the missing customer-level predictive pipeline more directly. It would be stronger evidence for **predicting future recorded transaction inactivity** than an aggregate-only experiment panel. It still would not prove confirmed churn, real-world generalization, calibrated customer probabilities, bank approval or retention uplift.

The model must be fitted and validated offline in a new research namespace, with a complete trusted bundle before UI use. Current artifacts cannot supply it. Additional label/coverage/selection/shift checks, multiple temporal evaluations, calibration assessment, feature/preprocessing parity, missing/out-of-domain handling and full baseline regression are necessary. A brief model wrapper alone cannot close those gaps.

The logistic recipe is a parsimonious research candidate with higher recorded AUC/AP than recency, but that one examined holdout cannot establish the final deployment choice. All three methods tie at Precision@500; HGB AP is worse than recency. New model complexity is not automatic competitive advantage.

The supplied official challenge emphasizes churn and AI/Data Analytics, but no score gain is assumed. A validated research demonstration may strengthen the story; an uncalibrated, artifact-mismatched or misleading probability screen can weaken it. No hackathon deadline or available implementation window was verified, so there is no promise that this work fits the remaining time.

## Likely live failures and safeguards to require later

- Missing fitted object/scaler, incompatible scikit/NumPy versions, omitted or double log1p, wrong feature order/precision.
- Snapshot cutoff/schema/unit/hash mismatch, upload that meets Phase 9's contract but not model semantics/support, insufficient history or out-of-domain values.
- Training on the target period and displaying those same cases as holdout; accidentally fitting or calibrating during rendering.
- Slow raw-source parsing/refitting in UI, changed alias/key/tie mapping or stale input/model state.
- A score presented as calibrated probability/confirmed churn or mixed with original SUPPORTED counts, commercial value, permissions or manager priority.
- Feed incompleteness/closure mistaken for inactivity; a new-data prevalence distribution interpreted through old unvalidated calibration.

Fail closed with research-only unsupported reasons; keep original app functional; use a fixed reviewed local bundle and validated snapshot, not runtime training or arbitrary model upload. Rehearse return to the unchanged baseline and verify all original cases/state hashes.

## Fallback recommendation

Option A can use the existing historical panel, source-bound acceptance receipts and already available sanitized/synthetic evidence; a prerecorded video is not a technical prerequisite. For any future Option B live pitch, strongly recommend a **validated frozen out-of-sample demonstration artifact and a clearly labelled prerecorded/screenshot fallback**, prepared only after authorization and model validation. Never call playback live inference or use fallback media to hide failed validity checks.

Use synthetic inputs or specifically authorized safe material; local model weights and derived scores from restricted banking data are not automatically approved for public upload. No new score batch, video, screenshots, fixtures, model or fallback artifact was generated during Phase 10C.

## Decision for the current pitch

**Keep Option A as the committed presentation on current evidence.** Option B is worth considering as a separately scoped research improvement, but not worth rushing in merely to add “live AI.” It becomes a credible choice only after the conditions in 06 are met. This audit neither authorizes that work nor changes existing challenge/acceptance reports.
